# 冰壶战术文本的视角切换与教案编排

冰壶课备课资料采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/赛表.json` | `id`、`match`、`end`、`colourA`、`colourB`、`hammer`、`direction` |
| `资料/逐投记录.json` | `id`、`end`、`shot`、`observer`、`text` |
| `资料/教学计划.json` | `id`、`reader`、`start`、`end`、`angle` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围（左闭右开的字符区间）定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 工具总览

在 `readMaterials` 之上，`src/` 提供纯 ESM、无第三方依赖的备课工具：

| 模块 | 职责 |
| --- | --- |
| `src/model.js` | 事实模型：实体对齐、子句切分与分类、视角方向校验、裁判更正、待确认项 |
| `src/lesson.js` | 教学包：学员练习与教员复盘双视图、答案隐藏、开放性审计、起点调整 |
| `src/compare.js` | 两回合对照：独立面板、串场拦截、同页开放性结论 |
| `src/print-log.js` | 印刷日志：按班次登记并查询已印练习当时的视角与依据（ndjson） |
| `src/cli.js` | 命令行入口，支持人读预览与 `--json` 机器输出 |

## 命令行用法

```sh
# 事实模型（JSON）：回合、投壶方、子句分类、更正、待确认项
node src/cli.js facts

# 单个教学计划的学员/教员双视图预览；--start 可调整问题起点
node src/cli.js lesson --plan p1
node src/cli.js lesson --plan p1 --start 4
node src/cli.js lesson --plan p1 --json

# 两个回合的对照审计（必须是同一赛事的两个不同回合）
node src/cli.js compare --plans p1,p3

# 登记一次印刷，按班次/班级留档；日志路径可用 --logfile 指定
node src/cli.js print --plan p1 --batch 班次2026秋-03 --class 甲班
node src/cli.js query --batch 班次2026秋-03
node src/cli.js query --class 甲班 --plan p1
```

`--materials <目录>` 可指向另一份资料目录；`--logfile <文件>` 指定印刷日志位置，默认写在 `src/print-log.ndjson`（已被 git 忽略）。

## 领域规则与系统行为

### 1. 识别回合、投壶方、观察方向、行动者与被保护对象

- 赛表中的“蓝 岩溪”“白 柳甸”解析为颜色与队名，颜色简称与队名互为别名。
- “我方/我们/本队”解析为观察者本方，“对手/对方”解析为观察者对方；教练、裁判等中立观察者使用的代词无队伍锚点，列入待确认，不猜测指向。
- 投壶方由后手身份与双方交替先投的结构规则推导（奇数投非后手方先投），**不从比分倒推任何未叙述的动作**，推导依据随结果保留。
- “保护壶/中心壶”的归属优先取同句颜色词，其次取同句队伍指称（如“白方护着他们自己的中心壶”），都没有则待确认。

### 2. 区分假想战术、已发生行动与后来结果

每条记录先切句再切子句（保留字符区间），子句分为：`局势`、`行动`、`假想`、`结果`、`待定`、`更正`。

- “若/假如/应该考虑”等标记假想；假想即使引用了真实局势，也不是已发生事实。
- “局末……得一分”归为后来结果；“结果还没定”归为待定。
- 假想前提与已确认事实冲突时标注失效。例如 n3“把后手当成已拿到”与裁判 n5 的后手改判冲突，旧前提只能留在教员复盘里，不能作为战术依据。

### 3. 视角与左右方向

- 左右是随视角变化的相对方向：同一现场两条记录会规范到同一侧做一致性校验。n1（岩溪视角）“向左”与 n2（柳甸视角）“右手边”规范后同为左侧，互为印证。
- 渲染到目标视角时，代词显式化为“颜色（队名）”，视角相反时左右按词表翻转，并在注记中写明依据。
- 中立观察者给出的“左侧”等无视角锚点：**保留原方位**，列入待确认，等待教师选定有依据的视角，不自动翻转。
- 场地方向（北向/南向）没有更正证据时一律保留原值。

### 4. 裁判更正与旧卡重核

- n5“第一回合后手实际属白，表上把第二回合一栏抄串了”解析为更正：第一回合后手由蓝改白，第二回合数值未被改但标注“抄串”来源。
- 后手更正后，所有复用该回合的教学计划自动带 `recheckRequired` 与重核原因（含方位保留说明），印刷日志同样留痕。

### 5. 开放练习的答案隔离

学员视图只保留起始投之前的必要局势：

- 起始投的行动是开放题答案，一律隐藏；“结果还没定”等起始投判定同步隐藏。
- 假想、后来结果、裁判更正、指向后文的代称（“下一投”）、跨回合引用（“前回合”）均不得进入学员视图，每条隐藏内容都带原因与区间。
- 开放性检查全部通过才标记 `open: true`；若过滤后没有任何有依据的局势，题干明确提示“不得直接付印”。

### 6. 起点调整、回合对照与印刷留痕

- 教员用 `--start` 调整问题起点后，可见范围、隐藏审计与依据区间联动重算，并标记 `startAdjusted`。
- 两回合只能以独立面板对照，禁止把不同现场串成一场比赛；任一面板缺局势或泄露答案时，结论为“改写问题或说明不能合并”。
- 每次印刷按班次/班级登记当时采用的视角、后手依据、方位、重核结论、来源区间与内容哈希，可按班次、班级、计划查询。
